# 04. 검증

## 결론

규칙을 넣는 것과 규칙이 의도대로 동작하는 것은 다릅니다. 실제 트래픽을 흘려보내 7개 항목을 확인했고 전부 통과했습니다. 핵심 판단 기준은 nmap이 `closed`가 아니라 **`filtered`** 를 반환하는가였습니다.

## 검증 명령어

```bash
curl http://192.168.200.10     # 302 Found → 웹 포트 허용 확인
nmap -sS 192.168.200.10        # 80/tcp open, 나머지 filtered
ping 192.168.200.10            # 무응답 (ICMP 미허용, 정상)
```

- `curl`의 302는 정상입니다. DVWA가 로그인 페이지로 리다이렉트하는 응답으로, 웹 포트가 열려 있다는 뜻입니다.
- `ping` 무응답도 정상입니다. WAN→DMZ ICMP를 허용하지 않았기 때문입니다.

## 검증 항목 7개

| # | 항목 | 기대 결과 | 결과 |
|---|---|---|---|
| 1 | WAN → DMZ 웹 포트 | 허용 | 통과 |
| 2 | WAN → DMZ 그 외 포트 | filtered | 통과 |
| 3 | WAN → DMZ ICMP | 차단 | 통과 |
| 4 | DMZ → 관제망 5044 | 허용 | 통과 |
| 5 | DMZ → 관제망 그 외 | 차단 + 로그 | 통과 |
| 6 | DMZ → LAN net | 차단 + 로그 | 통과 |
| 7 | 차단 트래픽 로그 적재 | 확인 | 통과 |

## `closed`가 아니라 `filtered`여야 하는 이유

nmap 스캔 결과에서 이 둘의 차이가 방화벽 설계의 품질을 가릅니다.

- **`closed`** — 포트가 닫혀 있고, 방화벽/호스트가 RST를 돌려준 상태. 응답이 돌아왔으므로 외부에서 "여기 장비는 있는데 이 포트는 닫혔다"를 알 수 있습니다.
- **`filtered`** — 방화벽이 패킷을 조용히 드롭한 상태. 아무 응답이 없으므로 외부에서 포트의 존재 여부조차 판단할 수 없습니다.

Default Deny 규칙이 RST를 돌려주지 않고 드롭(Log)하도록 구성돼 있어야 `filtered`가 나옵니다. 이 값이 나온다는 것은 정책이 의도대로 "침묵"하고 있다는 확인입니다.

## 차단 로그 확인

6번·5번 항목은 단순 차단이 아니라 **차단 + 로그 적재**를 함께 확인했습니다. DMZ에서 LAN net으로 향하는 트래픽을 발생시킨 뒤, 해당 Block 규칙에 로그가 남는지 확인했습니다. 차단 로그가 남아야 침해 후 Lateral Movement 시도를 사후 분석할 수 있습니다.
